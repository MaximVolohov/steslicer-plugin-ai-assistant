# AI Assistant — плагин-ассистент на базе LLM для STE Slicer

Плагин добавляет в STE Slicer 7.10 (Stereotech, форк Cura 3.6) чат с ИИ-ассистентом. Пользователь описывает задачу текстом и прикладывает модель (STL/OBJ/3MF), фото или эскиз. Ассистент через MCP-инструменты:

- выбирает **режим печати 3D или 5D**, профиль, материал и настройки;
- загружает, анализирует, ориентирует и расставляет модели;
- запускает нарезку, сохраняет **G-code** и **проект 3MF**;
- объясняет решения таблицей «Параметр — Значение — Почему».

Каждый вызов инструмента виден в чате: аргументы, результат и время выполнения.

## Установка

1. Скопируйте папку `AIAssistant` в папку плагинов пользователя:
   `%APPDATA%\steslicer\7.10\plugins\AIAssistant`.
   Папку конфигурации можно открыть в слайсере через **Справка → Показать папку конфигурации**.
   Ещё вариант — выполнить `powershell -ExecutionPolicy Bypass -File dev\install.ps1 -Copy`.
2. Перезапустите STE Slicer. Внизу окна появится сообщение «Чат-ассистент запущен» с кнопкой **Открыть чат**.
3. Чат также открывается из меню **Расширения → AI Assistant → Открыть чат**. Он откроется в браузере по умолчанию по адресу `http://127.0.0.1:8765/`.

> **Почему чат открывается в браузере.** В дистрибутиве STE Slicer 7.10 нет QtWebEngine и QtWebChannel, поэтому встроить веб-окно в слайсер нельзя. Плагин автоматически использует запасной вариант из кейса: локальный HTTP-сервер и системный браузер. Транспорт в SPA сменный: если в сборке появится QtWebEngine, плагин откроет встроенное окно и будет работать через `QWebChannel`.

## Настройка подключения к LLM

В чате нажмите **⚙** (или выберите в меню **AI Assistant → Настройки LLM**) и заполните поля:

| Поле | Пример | Комментарий |
|---|---|---|
| Адрес API | `https://llm.example.org/v1` | Любой OpenAI-совместимый Chat Completions API. Путь до `/v1`, без `/chat/completions` |
| Ключ доступа | `sk-…` | Хранится в настройках слайсера (`steslicer.cfg`, ключи `ai_assistant/*`), в коде его нет. В интерфейсе показывается маской |
| Модель | `gpt-4o` | Кнопка **Проверить подключение** запрашивает `GET /models` и подставляет список моделей |
| Vision | вкл. | Передавать изображения как `image_url` (base64). Если модель их не принимает, ассистент сам повторит запрос без картинок |

Остальные параметры: температура, лимит шагов агента, таймаут запроса, проверка TLS-сертификата, папка для G-code и 3MF (по умолчанию `Документы\STE AI Assistant`), автооткрытие чата при запуске.

Сетевые особенности учтены. Для проверки TLS используется certifi вместе с хранилищем сертификатов Windows. Системный (VPN) прокси применяется к внешним адресам, а к `localhost` — нет.

## Использование

- Напишите задачу, например «Кронштейн под нагрузку, PETG, без поддержек», и прикрепите STL кнопкой 📎. Файлы можно также перетащить в окно или вставить из буфера (Ctrl+V).
- Ассистент сам пройдёт цепочку: принтер → загрузка модели → анализ геометрии → режим 3D/5D → материал → профиль и настройки → ориентация → нарезка → сохранение G-code и 3MF → объяснение.
- В боковой панели видны принтер, режим, материалы, модели на столе, прогресс и итог нарезки (время, масса). Там же кнопки **Нарезать**, **G-code** и **Проект 3MF**.
- Кнопка **■** останавливает агента, **＋** начинает новый диалог, **⇩** выгружает диалог в Markdown.

Примеры запросов:

- «Втулка из полиамида, наружный Ø30, будет работать на трение — подойдёт ли 5D?»
- «Сравни время печати при заполнении 20 % и 40 % и оставь более быстрый вариант»
- «Смени материал на ABS и перенастрой под него»
- «Сохрани текущие настройки как профиль "Кронштейны PETG"»

## MCP-сервер

Плагин реализует MCP-сервер (JSON-RPC 2.0 поверх HTTP, Streamable HTTP с JSON-ответами) по адресу `http://127.0.0.1:8765/mcp`. Поддерживаются методы `initialize`, `ping`, `tools/list` и `tools/call`. Встроенный агент ходит **через этот же диспетчер**: LLM получает тот же список инструментов, переведённый в формат `tools` OpenAI.

Пример подключения внешнего MCP-клиента:

```json
{ "mcpServers": { "ste-slicer": { "type": "http", "url": "http://127.0.0.1:8765/mcp" } } }
```

| Группа | Инструменты |
|---|---|
| Принтер и настройки | `get_machine_info`, `list_machines`, `set_active_machine`, `search_settings`, `get_settings`, `set_settings`, `reset_settings`, `list_user_changes`, `set_printing_mode` |
| Профили и материалы | `list_quality_profiles`, `set_quality_profile`, `create_profile`, `save_profile`, `list_materials`, `set_material` |
| Модели | `load_model`, `list_objects`, `get_object_info`, `move_object`, `rotate_object`, `scale_object`, `center_object`, `arrange_all`, `delete_object`, `clear_scene` |
| Нарезка и экспорт | `start_slice`, `get_slice_status`, `get_slice_result`, `export_gcode`, `save_project_3mf`, `compare_variants` |
| Анализ и экспертиза | `analyze_model`, `apply_orientation`, `get_recommendations`, `get_scene_snapshot` |

Координаты в инструментах: миллиметры, ось Z направлена вверх, ноль — центр стола. Для X и Y задаётся положение центра габарита модели, для Z — положение её низа.

## Как это устроено

```
SPA (web/: index.html, app.js, transport.js)          ← системный браузер
   │  HTTP (fetch) + Server-Sent Events  |  QWebChannel, если есть QtWebEngine
server/http_server.py — Router: /api/*, /api/events, /mcp   (только 127.0.0.1)
   │                                   │
agent/agent.py — цикл диалога с LLM  ──┤ agent/llm_client.py → OpenAI-совместимый API
   │ tools/call (in-process JSON-RPC)  │
mcpserver/server.py — MCP-сервер → mcpserver/tools_*.py → slicer/*.py → API STE Slicer
                                       analysis/geometry.py, knowledge/kb.py
```

- **Потоки.** Сцену и настройки можно менять только из главного потока Qt. Все обращения к API идут через `core/qt_thread.run_on_main` (`callLater` + ожидание с таймаутом). Долгие операции (нарезка, загрузка, расстановка) ждут в рабочих потоках, и интерфейс не замирает. Экспорт выполняется в рабочем потоке, как `WriteFileJob` в Cura: декоратор `call_on_qt_thread` в STE Slicer не проверяет текущий поток и при вызове из главного потока вызывает deadlock.
- **Режим 3D/5D.** Режим задаёт настройка `printing_mode`: `classic` — 3D, `cylindrical_full` — 5D. По ней `BackendManager` выбирает бэкенд: CuraEngine для 3D, `CylindricalBackend` и CliParser для 5D. В 5D деталь ставится в центр стола, её ось вращения должна быть вертикальной.
- **Анализ геометрии** (`analysis/geometry.py`, numpy) вычисляет:
  - целостность сетки;
  - кандидатов ориентации с площадью свесов (по `support_angle`), площадью опоры и высотой;
  - признак «тело вращения» (радиальный профиль вокруг главных осей) и рекомендацию режима.
- **База знаний** (`knowledge/kb.py`): семейства материалов, включая линейки Stereotech, и пресеты «цель → настройки» с обоснованием каждого значения.
- **История диалога** хранится в `%APPDATA%\steslicer\7.10\ai_assistant\history.json`, вложения — там же, в папке `uploads\`.

## Разработка и проверка

Все скрипты из `dev\` запускаются обычным Python 3.8+ вне слайсера.

| Команда | Что делает |
|---|---|
| `python dev\check_py35.py` | Статическая проверка совместимости с Python 3.5 слайсера: синтаксис (f-строки, аннотации, walrus…), API новее 3.5, наличие модулей в `python35.zip` |
| `powershell -File dev\install.ps1` | Ставит в папку плагинов junction на исходники: правки подхватываются после перезапуска слайсера |
| `python dev\make_samples.py` | Генерирует тестовые модели `dev\samples\` (труба на боку — кандидат в 5D, L-кронштейн — 3D) |
| `python dev\mcp_smoke.py` | Сквозной тест MCP при запущенном слайсере: сценарии 3D и 5D, экспорт и проверка G-code и 3MF, затем восстановление исходного состояния |
| `python dev\mock_llm.py` | OpenAI-совместимый мок LLM со сценарием инженера и проверкой формы протокола. В настройках: `http://127.0.0.1:8001/v1`, модель `mock-agent` |
| `python dev\chat_e2e.py --configure-mock` | Сквозной тест чата: загрузка модели → `/api/chat` → цикл агента → события SSE (запускать при работающем `mock_llm.py`) |
| `powershell -File dev\package.ps1 -Team <имя>` | Собирает архив для сдачи `<имя>.zip` со структурой `plugin/` + `results/`, без `__pycache__` |

Логи: `%APPDATA%\steslicer\7.10\steslicer.log` (строки `[AIAssistant]`) и `%APPDATA%\steslicer\stderr.log`.

### Результаты проверки (STE Slicer 7.10.12, Stereotech Hybrid 530 V5.2.4)

- `check_py35.py`: 33 файла, 0 проблем.
- `mcp_smoke.py`, сценарий 3D — **пройден**. Цепочка: загрузка → анализ («3D») → режим → PETG → профиль `draft` и настройки «прочность» → ориентация → снимок → нарезка (≈2,5 с) → G-code (`;PRINTING_MODE:[classic]`) и 3MF → сравнение заполнения 20 % и 60 % (5023 с против 7034 с).
- `mcp_smoke.py`, сценарий 5D: анализ распознаёт трубу как тело вращения (0,97), рекомендует 5D, ставит ось вертикально и в центр. **Нарезка 5D на тестовой машине не выполняется**: движок `glicer_console.exe` не проходит проверку лицензии (`CheckATSSLicence … GetRegistryValue failed`) и простаивает. Плагин распознаёт это примерно через 90 с и сообщает пользователю, что нужна активация. На активированном дистрибутиве 5D-нарезка идёт через штатный `CylindricalBackend`.
- `chat_e2e.py` с `mock_llm.py`: 14 вызовов инструментов, 0 ошибок, полный цикл от сообщения до экспорта G-code и 3MF за ≈9 с (без задержек настоящей LLM).

## Устранение неполадок

| Симптом | Что сделать |
|---|---|
| Нет пункта меню и сообщения при запуске | Проверьте путь `...\7.10\plugins\AIAssistant\plugin.json`, затем найдите в логе строку `Loaded plugin AIAssistant` |
| Порт 8765 занят | Плагин сам займёт следующий свободный порт (до 8784). Точный адрес есть в стартовом сообщении и в логе |
| «Нет связи с LLM API» или ошибка TLS | Проверьте адрес (обычно оканчивается на `/v1`), прокси и VPN. В крайнем случае отключите проверку сертификата |
| Модель не видит изображения | Включите Vision или выберите мультимодальную модель. Без vision ассистент работает по тексту и модели |
| «Результат устарел» при экспорте | После изменения сцены или настроек нужно нарезать заново (`start_slice` или кнопка «Нарезать») |
| «5D-движок glicer_console … не выполняет расчёт» | 5D-модуль дистрибутива не активирован. Выполните активацию по инструкции организаторов; режим 3D работает и без неё |
